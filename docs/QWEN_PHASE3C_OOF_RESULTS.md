# Phase 3C-OOF — methodologically clean Qwen/tree stacking

Phase 3C-OOF reruns the primary Phase 3C fusion model with leakage-safe
training features. For every one of the 2,245 preserved training questions, the
five Qwen logits were generated by a Qwen model trained without that question
and without any question from its source paper. The logits were then combined
with the unchanged 173 inference-safe Phase 3B similarity-tree features.

## Frozen protocol

- Base model: `Qwen/Qwen3.5-0.8B-Base`
- Revision: `dc7cdfe2ee4154fa7e30f5b51ca41bfa40174e68`
- Python/PyTorch/Transformers: 3.10.7 / 2.8.0+cu128 / 5.15.0.dev0
- XGBoost: 3.0.2
- Architecture: full-parameter five-label sequence classifier
- Prompt, tokenizer, labels, loss, optimizer, scheduler, batch settings,
  three-epoch schedule, BF16 dtype, and seed: unchanged from Phase 2D
- OOF split: the same five deterministic paper-grouped Phase 3B folds, seed 42
- Fold sizes: 449, 449, 449, 450, and 448 questions
- Training OOF coverage: 2,245/2,245 exactly once; paper overlap: zero
- Fusion input: five OOF Qwen logits + 173 Phase 3B tree features = 178 features
- Fusion model: XGBoost `multi:softprob`
- Fixed Phase 3C primary parameters: depth 2, learning rate 0.05, 200 trees,
  minimum child weight 5, subsample 0.8, column subsample 0.8, L2 1, L1 0
- Class weighting: unchanged square-root inverse-frequency weighting
- Validation Qwen features: a separate fixed-third-epoch Qwen refit trained on
  all 2,245 training questions
- Validation use: no training, early stopping, hyperparameter selection,
  checkpoint selection, thresholding, or other decision used the 924 validation
  examples. The complete procedure was hashed and locked before validation
  inference.

The full training-data Qwen refit reproduced the original Phase 2D selected
model SHA-256 exactly:
`020af0a83af773239e7e60e9983afad29cae3f31493c7073e9162e040b732814`.

## Unavoidable deviations from original Phase 3C

1. Each outer Qwen fit contains 171 optimizer steps rather than 213 because it
   trains on approximately four fifths of the training papers. All other Qwen
   optimization settings remain unchanged.
2. Original Phase 2D selected a checkpoint using validation macro-F1. The clean
   run cannot reuse this rule, so every Qwen fit uses the predeclared third/final
   epoch endpoint with no evaluation-based checkpoint selection. The original
   selected Phase 2D checkpoint was also the third-epoch endpoint.
3. A sixth Qwen fit on all training questions is necessary to provide base-model
   features for unseen validation questions, as in standard stacking.
4. The rerun covers the original primary five-logit fusion model. It does not
   rerun the non-primary 1,024-dimensional hidden-state exploratory variant.

| Phase 3C-OOF (clean) | 0.322511 | 0.209985 | 0.326741 | 0.217859 | 0.278303 |
| Original Phase 3C | 0.319264 | 0.230677 | 0.333987 | 0.235850 | 0.287202 |
| Phase 2D Qwen | 0.369048 | 0.229945 | 0.364466 | 0.239181 | 0.276717 |
| Phase 3B tree XGBoost | 0.329004 | 0.224670 | 0.329620 | 0.232723 | 0.271721 |

Clean Phase 3C-OOF minus original Phase 3C is +0.003247 accuracy,
-0.020691 macro-F1, and -0.008898 mean joined retrieval F1. It improves mean
retrieval F1 over Phase 2D by 0.001587 and over Phase 3B by 0.006582, but does
not reproduce the original Phase 3C retrieval gain.

## Interpretation

The original Phase 3C train-side OOF diagnostic used Qwen logits from a model
already trained on all 2,245 training questions. Its reported train OOF
accuracy/macro-F1 was 0.471715/0.383835. Under clean cross-fitted Qwen logits,
the fixed fusion candidate's train-only grouped diagnostic falls to
0.304232/0.231679. This large drop confirms that the old train-side stacking
diagnostic was optimistic because its base-model inputs were in-sample.

The untouched validation result is the decisive comparison. Cleaning the
stacking inputs does not materially improve exact evidence-length-label
accuracy and reduces macro-F1 and downstream retrieval F1 relative to original
Phase 3C. The fusion still slightly exceeds either learned component's retrieval
F1 alone, but remains below fixed 20, 40, and 80. The result supports the prior
finding that question-only Qwen signals and similarity-tree features provide
limited information about the evidence-length target, and that higher exact
agreement with this proxy is not equivalent to retrieval-optimal routing.

## Reproduction

On a CUDA BF16 host with the existing Python 3.10.7 `.venv-fusion` environment:

```bash
bash scripts/run_phase3c_oof_remote.sh /workspace/thesis-granularity-router
```

The script expands to:

```bash
python qwen_phase3c_oof.py audit
for fold in 0 1 2 3 4; do
  python qwen_phase3c_oof.py train-fold --fold "$fold"
done
python qwen_phase3c_oof.py assemble-oof
python qwen_phase3c_oof.py train-full
python qwen_phase3c_oof.py freeze
python qwen_phase3c_oof.py extract-validation
python qwen_phase3c_oof.py train-evaluate
```

After copying the output tree to the machine hosting the unchanged Qdrant
collections:

```powershell
.\.venv-qwen\Scripts\python.exe qwen_phase3c_oof.py retrieve
.\.venv-qwen\Scripts\python.exe qwen_phase3c_oof.py finalize
python -m unittest tests.test_qwen_phase3c_oof -v
```
