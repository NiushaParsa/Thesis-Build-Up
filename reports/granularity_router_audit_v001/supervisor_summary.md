# Granularity router: concise technical summary

The current router is a five-class classifier that maps one QASPER question embedding to one chunk size: 10, 20, 40, 80, or 160 tokens. One example corresponds to one answerable question (a question having at least one non-empty highlighted-evidence string). The only input feature is its 1,536-dimensional `text-embedding-3-small` vector; evidence text, evidence length, retrieval metrics, paper ID, and question text are not additional features.

Oracle targets were generated by retrieving the top five same-paper chunks separately at each candidate granularity. The five retrieved chunk texts were concatenated in rank order with newline separators. After lower-casing, punctuation removal, and whitespace normalization, GPT-2 tokens were used for SQuAD-style multiset token precision, recall, and F1 against the concatenation of the question's unique highlighted-evidence strings. The primary target maximizes joined top-five F1. Values within `1e-6` of the maximum are tied; ties are resolved by mean maximum chunk-to-evidence embedding similarity, then by the smaller chunk size. Evidence length is not a label-selection criterion, although it indirectly affects precision/recall/F1 because the evidence text is the reference.

The official QASPER paper splits are retained. The current artifact was trained on 2,245 questions from 845 train papers and tuned on 924 questions from 277 validation papers. Questions without valid evidence were filtered; Oracle rows also require all five granularities and at least one retrieved chunk at each. The loader checks both question IDs and document IDs across splits and rejects leakage. The artifact did not load or evaluate test, and the local RouterDataset has zero test Oracle records for its configuration hash, so no defensible test or all-three-split histogram can be reported.

Oracle label distribution:

| Split | 10 | 20 | 40 | 80 | 160 |
|---|---:|---:|---:|---:|---:|
| Train (n=2,245) | 460 (20.49%) | 675 (30.07%) | 686 (30.56%) | 343 (15.28%) | 81 (3.61%) |
| Validation (n=924) | 137 (14.83%) | 235 (25.43%) | 283 (30.63%) | 187 (20.24%) | 82 (8.87%) |
| Available train+validation (n=3,169) | 597 (18.84%) | 910 (28.72%) | 969 (30.58%) | 530 (16.72%) | 163 (5.14%) |
| Test | unavailable | unavailable | unavailable | unavailable | unavailable |

The distribution is moderately imbalanced, especially for 160 tokens. The train-majority class is 40 tokens (30.56% of train); always predicting it gives 30.63% validation accuracy. The selected logistic router obtains 24.78% validation accuracy and 0.2149 macro-F1. Its predicted validation distribution is 10: 171 (18.51%), 20: 260 (28.14%), 40: 298 (32.25%), 80: 164 (17.75%), and 160: 31 (3.35%). Thus it substantially underpredicts the rare 160 class (3.35% predicted versus 8.87% true). Its macro-F1 exceeds the majority baseline (0.2149 versus 0.0938), but its raw accuracy is lower.

Training used standardized embeddings (mean and standard deviation fitted on train only), AdamW, unweighted cross-entropy, batch size 64, and exactly 200 epochs with no early stopping. Logistic candidates used learning rates 0.01/0.001 and weight decays 0/0.0001; the selected candidate used 0.01, 0.0001, seed 43. The MLP was 1,536→64→5 with ReLU and dropout 0.1, learning rate 0.001, weight decay 0, seed 10042. Candidates were selected by validation macro-F1, then accuracy; the MLP would replace logistic only with at least +0.01 macro-F1. Its observed gain was only +0.0038, so logistic was retained.

## Qwen3.5-0.8B Phase 1 — Pretrained Zero-Shot Router

### 1. Objective

Phase 1 evaluates the pretrained `Qwen/Qwen3.5-0.8B` router before supervised
fine-tuning. No fine-tuning was performed, no optimizer was created, and no
gradients or backward passes were used. No LoRA, QLoRA, adapters, prompt
tuning, or classification-head training occurred. The number of parameter
updates was exactly zero. This completed frozen zero-shot run is the Phase 1
baseline; supervised fine-tuning is reserved for Phase 2.

### 2. New Oracle definition

The previous Oracle selected the granularity producing the highest joined
top-five retrieval F1. The new Oracle follows the supervisor's confirmed
definition: calculate the GPT-2 token length of the complete deduplicated
ground-truth evidence and select the numerically closest candidate from 10,
20, 40, 80, and 160. Exact midpoint ties select the smaller candidate.
Evidence below 10 tokens maps to 10, and evidence above 160 tokens maps to
160.

This Oracle is independent of retrieval F1, embedding quality, cosine
similarity, retrieved chunks, and router performance.

### 3. Dataset and input

The preserved official QASPER data contains 2,245 train examples and 924
validation examples; validation covers 277 papers. Candidate classes are 10,
20, 40, 80, and 160. Downstream retrieval remains top-k = 5 and is restricted
to the source paper.

Logistic Regression and MLP use 1,536-dimensional question embeddings. Qwen
receives only the fixed routing instruction and original question text. It was
not supplied with evidence, evidence length, answers, paper text, retrieved
chunks, retrieval scores, metadata, or handcrafted features.

### 10. Interpretation

The pretrained zero-shot Qwen router performed substantially below the
majority-class baseline on evidence-length-Oracle label prediction and
strongly favored the smallest class. This result motivates supervised
fine-tuning using the new Oracle labels. Phase 1 remains a frozen baseline for
comparison with Phase 2; the poor zero-shot classification result does not
establish that Qwen is unsuitable after fine-tuning.

### 11. Comparability warning

The previous Logistic Regression and MLP classification results used the old
retrieval-F1 Oracle. They are therefore not directly comparable with this
new evidence-length-Oracle Qwen result. Future fair comparisons should train
and evaluate all routers using the same new Oracle labels and preserved
splits.
