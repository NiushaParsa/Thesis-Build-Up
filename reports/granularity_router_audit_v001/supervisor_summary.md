# Granularity router: concise technical summary

The current router is a five-class classifier that maps one QASPER question embedding to one chunk size: 10, 20, 40, 80, or 160 tokens. One example corresponds to one answerable question (a question having at least one non-empty highlighted-evidence string). The only input feature is its 1,536-dimensional `text-embedding-3-small` vector; evidence text, evidence length, retrieval metrics, paper ID, and question text are not additional features.

Oracle targets were generated by retrieving the top five same-paper chunks separately at each candidate granularity. The five retrieved chunk texts were concatenated in rank order with newline separators. After lower-casing, punctuation removal, and whitespace normalization, GPT-2 tokens were used for SQuAD-style multiset token precision, recall, and F1 against the concatenation of the question's unique highlighted-evidence strings. The primary target maximizes joined top-five F1. Values within `1e-6` of the maximum are tied; ties are resolved by mean maximum chunk-to-evidence embedding similarity, then by the smaller chunk size. Evidence length is not a label-selection criterion, although it indirectly affects precision/recall/F1 because the evidence text is the reference.

The official QASPER paper splits are retained. The current artifact was trained on 2,245 questions from 845 train papers and tuned on 924 questions from 277 validation papers. Questions without valid evidence were filtered; Oracle rows also require all five granularities and at least one retrieved chunk at each. The loader checks both question IDs and document IDs across splits and rejects leakage. The artifact did not load or evaluate test, and the local RouterDataset has zero test Oracle records for its configuration hash, so no defensible test or all-three-split histogram can be reported.

Oracle label distribution:

| Split | 10 | 20 | 40 | 80 | 160 |
|---|---:|---:|---:|---:|---:|
| Train (n=2,245) | 460 (20.49%) | 675 (30.07%) | 686 (30.56%) | 343 (15.28%) | 81 (3.61%) |
| Validation (n=924) | 137 (14.83%) | 235 (25.43%) | 283 (30.63%) | 187 (20.24%) | 82 (8.87%) |
| Available train+validation (n=3,169) | 597 (18.84%) | 910 (28.72%) | 969 (30.58%) | 530 (16.72%) | 163 (5.14%) |
| Test | unavailable | unavailable | unavailable | unavailable | unavailable |

The distribution is moderately imbalanced, especially for 160 tokens. The train-majority class is 40 tokens (30.56% of train); always predicting it gives 30.63% validation accuracy. The selected logistic router obtains 24.78% validation accuracy and 0.2149 macro-F1. Its predicted validation distribution is 10: 171 (18.51%), 20: 260 (28.14%), 40: 298 (32.25%), 80: 164 (17.75%), and 160: 31 (3.35%). Thus it substantially underpredicts the rare 160 class (3.35% predicted versus 8.87% true). Its macro-F1 exceeds the majority baseline (0.2149 versus 0.0938), but its raw accuracy is lower.

Training used standardized embeddings (mean and standard deviation fitted on train only), AdamW, unweighted cross-entropy, batch size 64, and exactly 200 epochs with no early stopping. Logistic candidates used learning rates 0.01/0.001 and weight decays 0/0.0001; the selected candidate used 0.01, 0.0001, seed 43. The MLP was 1,536→64→5 with ReLU and dropout 0.1, learning rate 0.001, weight decay 0, seed 10042. Candidates were selected by validation macro-F1, then accuracy; the MLP would replace logistic only with at least +0.01 macro-F1. Its observed gain was only +0.0038, so logistic was retained.

## Qwen3.5-0.8B Phase 1 — Pretrained Zero-Shot Router

### 1. Objective

Phase 1 evaluates the pretrained `Qwen/Qwen3.5-0.8B` router before supervised
fine-tuning. No fine-tuning was performed, no optimizer was created, and no
gradients or backward passes were used. No LoRA, QLoRA, adapters, prompt
tuning, or classification-head training occurred. The number of parameter
updates was exactly zero. This completed frozen zero-shot run is the Phase 1
baseline; the subsequently completed supervised fine-tuning is reported in
the separate Phase 2 section below.

### 2. New Oracle definition

The previous Oracle selected the granularity producing the highest joined
top-five retrieval F1. The new Oracle follows the supervisor's confirmed
definition: calculate the GPT-2 token length of the complete deduplicated
ground-truth evidence and select the numerically closest candidate from 10,
20, 40, 80, and 160. Exact midpoint ties select the smaller candidate.
Evidence below 10 tokens maps to 10, and evidence above 160 tokens maps to
160.

This Oracle is independent of retrieval F1, embedding quality, cosine
similarity, retrieved chunks, and router performance.

### 3. Dataset and input

The preserved official QASPER data contains 2,245 train examples and 924
validation examples; validation covers 277 papers. Candidate classes are 10,
20, 40, 80, and 160. Downstream retrieval remains top-k = 5 and is restricted
to the source paper.

Logistic Regression and MLP use 1,536-dimensional question embeddings. Qwen
receives only the fixed routing instruction and original question text. It was
not supplied with evidence, evidence length, answers, paper text, retrieved
chunks, retrieval scores, metadata, or handcrafted features.

## Qwen3.5-0.8B Phase 2B — Restricted-Alias Full-Parameter Experiments

### 1. Objective and experimental boundary

Phase 2B evaluates whether a restricted five-alias formulation improves the

unweighted counterpart. Both variants fine-tune the same
`Qwen/Qwen3.5-0.8B` revision
`2fc06364715b967f1860aea9cf38778875588b17`. All 852,985,920 model parameters
were trainable; each run used gradients, backward passes, AdamW, and 213
optimizer/parameter updates. Neither run used LoRA, QLoRA, adapters, prompt

input features. Phase 1 and Phase 2 remain frozen and were not overwritten.

## Qwen3.5-0.8B-Base Phase 2C — Five-Logit Sequence Classification

### 1. Supervisor motivation and objective

Phase 2C evaluates the supervisor-motivated direct-classification alternative
to the preceding generative and next-token router formulations. The intended
change is to use a Base checkpoint, attach a conventional five-class sequence
classification head, and express the choices as semantic context-length
categories in a revised instruction. This avoids using generated text,
assistant target tokens, or a parser as the classification interface.

The exact model is `Qwen/Qwen3.5-0.8B-Base`, revision
`dc7cdfe2ee4154fa7e30f5b51ca41bfa40174e68`. The exact instruction is:

Based only on the question, select the option representing the context size most suitable for retrieving the evidence required to answer it. Choose exactly one value from: 1 = very short context, 2 = short context, 3 = medium context, 4 = long context, 5 = very long context. Return only the number

### 2. Formulation and leakage boundary

Phase 2C uses `AutoModelForSequenceClassification` with five output logits.
Class IDs 0, 1, 2, 3, and 4 map to chunk sizes 10, 20, 40, 80, and 160. The
bias-free classifier parameter is `score.weight` with shape 5×1024. Training
uses uniform, unweighted, single-label five-class cross-entropy; inference is
deterministic argmax over the five comparable head logits. Top-2 accuracy is
therefore available from the same logits.

There is no unrestricted generation, restricted next-token generation, chat
template, assistant answer target, decoding procedure, output parser, parser
fallback, or default chunk size. The only semantic inputs are the fixed prompt
and original question text. The model receives no evidence, evidence length,
answer, paper text, retrieved chunk, retrieval score, metadata, question
embedding, or handcrafted feature.

The train sequence-length range is 86--112 tokens, mean
92.13363028953229. Validation is 87--115, mean 91.59740259740259. No example
exceeds the maximum sequence length of 128, and no input is silently truncated.

## Qwen3.5-0.8B-Base Phase 2D — Exact-Token Prompt Ablation

### 1. Objective and controlled experimental boundary

Phase 2D tests one specific question raised after Phase 2C: whether replacing
qualitative context descriptions with the exact candidate token counts changes
the conventional five-logit classifier's behavior. It is a fresh training run
from the same pretrained Base checkpoint, not continued training from the
Phase 2C checkpoint.

The saved Phase 2C-to-Phase 2D protocol audit passed. It identifies the run as
a `prompt_only_single_seed_ablation` and verifies equality of the model,
revision, classifier architecture, deterministic seed and initial head,
non-prompt training configuration, frozen dataset and Oracle hashes,
checkpoint-selection rule, and downstream retrieval identity. The only
semantic change is:

- Phase 2C: `1 = very short context, 2 = short context, 3 = medium context, 4 = long context, 5 = very long context`;
- Phase 2D: `1 = 10 tokens, 2 = 20 tokens, 3 = 40 tokens, 4 = 80 tokens, 5 = 160 tokens`.

Run IDs, timestamps, code hashes, output paths, experiment fingerprints, and

### 2. Prompt, model input, and leakage boundary

The exact Phase 2D instruction is:

> You are a router for a retrieval-augmented generation system. Based only on the question, select the option representing the context size most suitable for retrieving the evidence required to answer it. Choose exactly one value from: 1 = 10 tokens, 2 = 20 tokens, 3 = 40 tokens, 4 = 80 tokens, 5 = 160 tokens. Return only the number

## Qwen3.5-0.8B-Base Phase 2E — Predeclared Learning-Rate Grid and Five-Epoch Development Selection

### 1. Objective and controlled design

Phase 2E tests whether a lower learning rate and five-epoch schedule improve
the Phase 2D sequence-classification router. It consists of three independent
runs at `5e-6`, `1e-5`, and `2e-5`. Every run starts freshly from
`Qwen/Qwen3.5-0.8B-Base`; no Phase 2D or Phase 2E trained checkpoint initializes
another trial. The only within-Phase-2E difference is learning rate.

All other settings are frozen: model revision
`dc7cdfe2ee4154fa7e30f5b51ca41bfa40174e68`, the Phase 2D exact-token prompt,
the same tokenizer, preserved train/validation examples and Oracle files,
question-only input, five-logit `AutoModelForSequenceClassification` head,
uniform cross-entropy, full-parameter configuration, seed 42, maximum length
128, microbatch 4, gradient accumulation 8, effective batch 32, weight decay
0.01, cosine schedule, warmup ratio 0.05, gradient clipping 1.0, BF16 CUDA,
and no quantization. Each trial runs five epochs/355 optimizer updates, with 18
warmup steps and validation at steps 71, 142, 213, 284, and 355.

The fixed instruction remains:

> You are a router for a retrieval-augmented generation system. Based only on the question, select the option representing the context size most suitable for retrieving the evidence required to answer it. Choose exactly one value from: 1 = 10 tokens, 2 = 20 tokens, 3 = 40 tokens, 4 = 80 tokens, 5 = 160 tokens. Return only the number

Its SHA-256 is
`b3237368922abe709e2bd2d756fb9f25d39e7f5670e5c4cb15daaa3a2d1cf2e5`.
The input is the instruction, a blank line, and the original question text.
No evidence, evidence length, answer, paper text, retrieved chunks or scores,
metadata, handcrafted feature, chat template, or assistant target is supplied.

### 8. Interpretation and limitations

The lower `5e-6` rate is the Phase 2E winner, but the gain within the grid is
small: its epoch-4 macro-F1 exceeds its epoch-5 runner-up by
0.0021861577015921674. Phase 2E did not solve minority behavior, did not beat
Phase 2D on the primary metric, and should be preserved as a negative/neutral
hyperparameter-tuning result rather than an improvement claim.

The official 924-example validation split has selected among 15 Phase 2E
checkpoints and has also been repeatedly inspected in prior phases. It is now
a development/model-selection set, not an unbiased final generalization
estimate. Selection optimism is expected. Only seed 42 was run, so no variance,
confidence interval, statistical significance, or QASPER test claim is
available. The three learning rates are not three random-seed replicates.
Earlier Logistic Regression and MLP classifiers use the old retrieval-F1
Oracle, so their classification results are not directly comparable.
